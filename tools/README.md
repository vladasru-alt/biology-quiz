# Инструменты банка вопросов

Скрипты для проверки, правки и выкладки тренажёра. Как они встраиваются в работу, описано в [PIPELINE.md](../PIPELINE.md).

Запуск — из корня репозитория, нужен Node.js 18 или новее, без зависимостей. Рабочие файлы (выгрузки, пакеты для агентов, результаты, сводки) пишутся в `tools/work/`, папка не попадает в git. Другую папку можно задать переменной `QUIZ_WORK`.

До 06.10.2026 эти скрипты жили во временной папке сессии. Когда её очистили, их пришлось восстанавливать из истории переписки, а список удалённых номеров — из истории git. Поэтому теперь всё лежит здесь.

## Цикл одной правки главы

```bash
node tools/prep-chapter.js ch5 4 tools/work/review/fix-input.json   # пакеты главы с целями длины и находками
# … агент-редактор возвращает result.json по каждому пакету …
node tools/lint-result.js result.json ch5 tools/work/prep/ch5-A.json # проверка результата против пакета
node tools/splice.js result.json ch5 --dry                          # пробная вставка
node tools/splice.js result.json ch5                                # вставка в quiz-data.js (один раз!)
node tools/lint-bank.js                                             # сводный линтер всего банка
node tools/lang-scan.js                                             # языковой скан
# прогон в браузере (см. ниже), коммит, push и
sh tools/check-live.sh https://vladasru-alt.github.io/biology-quiz/
```

Для рецензентов вместо пакетов нужна полная выгрузка: `node tools/dump.js`.

## Что есть

| Файл | Что делает |
|---|---|
| `lib.js` | Общие пути (`ROOT`, `BANK`, `WORK`, `RETIRED`), загрузка банка, ранг правильного варианта по длине, разброс. **Правила стандарта** (`MAX_SPREAD`, `MAX_WHY_SENT`, `WHY_SOFT_LIMIT`, формулы multi и пояснения) и **проверка структуры вопроса** `structure()` — одни на все линтеры. Справочники `SKILLS`, `LEVELS` и запрещённые варианты терминов `BANNED_TERMS` — **свои для каждого предмета** |
| `serq.js` | Сериализатор вопроса в формат банка: фиксированный порядок полей и отступы. Все 633 блока банка совпадают с его выводом побайтово |
| `splice.js result.json chN [--dry]` | Вставка правок главы: замена блоков по id, удаление (id уходит в `retired.json`), новые вопросы с временным id `NEW-…` — в конец главы с номером `max(есть ∪ удалённые) + 1`. Незнакомый «настоящий» id вида `ch5-21` — ошибка (скорее опечатка), id в `deleted` не из этой главы — предупреждение. Перед записью итоговый файл разбирается и проверяется на дубли id. **Повторный запуск того же файла снова добавит его новые вопросы** |
| `retired.json` | Номера удалённых вопросов. **Без него новый вопрос может получить номер удалённого, и история ученика припишется чужому вопросу.** Восстановлен из истории git: id, которые были в каком-либо коммите и которых нет сейчас, плюс ch3-068 и ch4-002, удалённые до первого коммита с id. Новый предмет начинает с `[]` |
| `prep-chapter.js chN K [fix-input.json] [gaps.json]` | Пакеты главы для редакторов: K блоков по темам, у вопросов цели `_цель_options`/`_цель_reasons` («оставить» или нужное место по длине, по главе около 25/25/50 %), находки `_находки`, пробелы. Плюс `chN-stems.json` — условия главы |
| `dump.js [папка]` | `chN.json` с полями `_len`/`_lenReasons` (длины вариантов и место правильного) и `all-compact.txt` — весь банк по три строки на вопрос для поиска дублей и противоречий |
| `lint-bank.js [файл]` | Сводный линтер: статистика по главам, ОШИБКИ (структура, метаданные, id, форматы, разброс, термины; код выхода 1) и предупреждения (известные отклонения), межглавные почти-дубли |
| `lint-result.js result.json chN [исходник.json]` | Проверка результата агента до вставки: те же правила плюс место правильного по целям пакета или как в исходнике (у новых — середина), неизвестные id, с исходником — потерянные id |
| `check-fix.js result.json` | Сверка исправлений рецензии с банком: сохранилось ли место правильного, не вырос ли разброс и пояснение |
| `check-new.js chN new.json` | Проверка новых вопросов (на пробелы) по стандарту, включая метаданные |
| `diff-chapter.js result.json chN` | Какие поля и в скольких вопросах изменены |
| `show.js file.json [ch1 \| ch1-00 \| ch1-005,…]` | Вопросы для чтения глазами: ✔ у верного, пояснение с длиной. `ch1` — вся глава 1 (без ch10) |
| `merge.js v1.json правка.json out.json` | Свести первую редактуру главы и правку по отчёту критика |
| `lang-scan.js [файл]` | Языковой скан банка: точки с запятой, скобки, канцелярит (25 шаблонов), скопления сокращений, длинные предложения и пояснения, условия из отглагольных существительных, числа без разрядов |
| `lang-kanc.js [файл]` | Канцелярит по 30 шаблонам с частотами и примерами; реплики в служебных текстах в конце `quiz-data.js` (`supportText` и далее), которые додумывают чувства ученика. Тексты `index.html` не читает |
| `lang-check.js result.json` | Разбор итога языковой редактуры и сверка: смысл и метаданные не менялись, место правильного сохранилось, пояснение не выросло, термины. При замечаниях код выхода 1 |
| `review-summary.js result.json имя` | Сохранить часть полной рецензии в `work/review/res-<имя>.json` и вывести сводку с вердиктами скептиков |
| `review-summary.js --merge [имена…]` | Свести части круга (например `A B C APP`) в `work/review/fix-input.json` для исправлений и `gaps.json`. Без имён берёт все `res-*.json` — перед новым кругом старые лучше убрать |
| `gaps-save.js result.json` | Разбор итога процесса пробелов: новые вопросы по главам, отсеянные пробелы |
| `check-live.sh URL` | После `git push` ждёт, пока GitHub Pages отдаст `index.html` и `quiz-data.js`, побайтово совпадающие с локальными |
| `browser/runner.js` | Робот для браузера (см. ниже) |
| `workflows/` | Скрипты многоагентных процессов, которыми писали и проверяли банк. Это шаблоны: пути заменены на `<репозиторий>` и `<рабочая папка>`, правила и списки ловушек — от биологии. Перед запуском подставить свои пути и материалы |

`result.json` — либо файл вывода многоагентного процесса (`{"result": "…"}`), либо готовый JSON `{questions, deleted}`: все скрипты читают оба формата.

## Прогон в браузере

1. Запустить сервер из корня репозитория: `python3 -m http.server 8753`. В Claude Code для этого есть локальная конфигурация `bio-quiz` в `.claude/launch.json`, но в репозиторий она не входит.
2. Открыть `http://localhost:8753/` и войти под тестовым именем.
3. В консоли страницы:

```js
eval(await (await fetch('/tools/browser/runner.js')).text());
await __runAll()          // все главы: ждём «chN: N из N» по каждой и пустую консоль ошибок
await __runChapter('ch5') // одна глава
await __ans(false)        // ответить на текущий вопрос заведомо неверно — для сценарных проверок
```

- После `location.reload()` робот восстанавливается так: `eval(sessionStorage.getItem('__runnerLib'))`.
- Подтверждения «выйти?» и «начать заново?» робот принимает сам.
- `__runAll` удаляет незаконченные прохождения **всех** пользователей этого браузера, поэтому запускать его надо под тестовым профилем.
- Префикс ключей хранилища (`bio_`) задан в начале файла.

## Известные отклонения банка

`node tools/lint-bank.js` сейчас выдаёт 1 ошибку и 27 предупреждений:
- **ошибка:** ch3-023, вариант «Протеиназы» вместо единого термина «протеазы»;
- 23 из 42 сопоставлений: разброс длины правой колонки больше 5 символов (раньше линтер его не проверял);
- 3 вопроса с несколькими ответами кончаются не на «Отметьте все верные.»: ch4-008, ch4-037, ch10-036;
- ch7-020: вариант со строчной «pH» после «?» — допустимое исключение.

Отдельным счётчиком в итоговой строке: 26 пояснений длиннее 330 знаков. Это ориентир, а не правило.

После исправления `\b` языковой скан впервые считает канцелярит: 27 мест, чаще всего «происходит» (15), и 10 условий из отглагольных существительных. Многие «данные» — это научные данные, а не канцелярит.

## Для другого предмета

- `lib.js`: поменять справочники `SKILLS`, `LEVELS` и `BANNED_TERMS`.
- `lang-scan.js`: поменять `ABBR_OK` — общеизвестные сокращения.
- `browser/runner.js` и `index.html`: поменять префикс ключей хранилища.
- `retired.json`: начать с `[]`.

Для числовых вариантов правило длины не подходит, см. PIPELINE.md, раздел 8.3.
